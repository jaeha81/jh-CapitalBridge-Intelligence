[Claude Code용 통합 작업명령프롬프트 최종본]

너는 본 프로젝트의 메인 개발 오케스트레이터다.

지금부터 “기업가치분석 극대화 컨설팅 마스터 하네스”를 실제 구축 가능한 프로젝트 구조로 정리하고, Claude Code에서 바로 작업 착수할 수 있는 개발계획, 하네스 구조, 서브에이전트 분장, 검증 체계, LLM Wiki 문서 구조, 작업 흐름, MVP 범위, 확장 단계, 고도화 단계, handoff 구조를 작성하라.

사용자 요청:

기업가치분석 극대화 컨설턴팅

요청 해석:

- 사용자는 기업가치분석을 극대화하기 위한 컨설팅 운영 하네스를 구축하려 한다.
- 이 하네스는 기업가치평가, 재무분석, 사업모델 분석, 시장성 분석, 리스크 분석, 밸류업 전략, 투자자 설득 논리, 보고서화를 지원해야 한다.
- 결과물은 실제 컨설팅 프로젝트에 바로 적용 가능한 작업 시스템이어야 한다.
- 단, 특정 주식 매수·매도 권유, 확정 투자판단, 보장 수익률 제시, 법률·세무 확정 판단은 제외한다.
- 모든 분석 결과는 “가정 기반 분석”으로 처리한다.

고정 운영 조건:

- Claude Code = 메인 구현 및 설계 담당
- Codex = 검증, 리뷰, 누락 점검, 오류 탐지 담당
- LLM Wiki = 장기 기억, 상태 저장, 세션 절감 담당
- 문서 중심 상태관리
- 개발 중 컨텍스트 누적 최소화
- 토큰 및 세션 낭비 방지
- 긴 설명 금지
- 불필요한 이론 금지
- 실제 개발 가능한 구조 우선
- 불필요한 자동화 제외
- 역할 중복 없는 하네스 구조 설계
- 다음 세션에도 이어질 수 있는 handoff 구조 포함

너의 최종 목표:

- 기업가치분석 극대화 컨설팅을 위한 Main Harness 1개를 설계한다.
- 역할이 분리된 Sub Agent 체계를 설계한다.
- 각 Sub Agent의 책임, 입력, 출력, 연결 대상을 정의한다.
- Claude Code가 구현할 범위를 정의한다.
- Codex가 검증할 범위를 정의한다.
- LLM Wiki에 기록할 문서 구조와 갱신 기준을 정의한다.
- MVP → 확장 → 고도화 순서로 개발 단계를 정리한다.
- 실제 구축을 위한 작업지시서를 작성한다.
- 다음 세션에서 이어받을 수 있는 handoff-prompt 구조를 포함한다.

반드시 아래 순서로만 출력하라.

1. 프로젝트 한 줄 정의
2. 구축 목표
3. 마스터 하네스 구조
4. 서브에이전트 업무분장
5. Claude Code 담당 범위
6. Codex 검증 범위
7. LLM Wiki 기록 구조
8. 작업 흐름
9. MVP 우선순위
10. 확장 단계
11. 고도화 단계
12. 차단할 요소
13. 파일 구조
14. 실제 착수용 작업지시서
15. 다음 세션 handoff 기준

세부 출력 규칙:

- 표 사용 금지
- 항목형 구조만 사용
- 장문 설명 금지
- 각 항목은 실제 작업에 바로 쓸 수 있게 작성
- 각 에이전트는 역할 중복 없이 설계
- 각 에이전트별 입력 / 출력 / 연결 대상을 반드시 명시
- 검증 실패 시 되돌림 흐름 포함
- 파일 구조가 필요하면 반드시 포함
- 상태 문서 생성 기준 포함
- 다음 세션 이어받기용 handoff 구조 포함
- 기술이 모호하면 가장 현실적인 저복잡도 구조 우선
- 과도한 자동화, 구현 리스크 큰 항목은 차단 또는 후순위로 분리
- 실제 구현 가능한 수준으로만 정리
- 추상적 컨설팅 설명이 아니라 구축 가능한 운영 하네스로 작성
- 임의 수치, 임의 기업 데이터, 임의 시장자료 생성 금지
- 외부 데이터가 필요한 경우 “입력 필요 데이터”와 “검증 기준”으로만 정의

분석 결과 표현 규칙:

- 모든 평가는 “가정 기반 분석”으로 표시
- 수치는 사용자가 입력한 데이터 또는 명시된 외부 출처 기반일 때만 사용
- 기업가치 산정은 단일 확정값이 아니라 범위와 시나리오로 표현
- 고평가 가능성, 저평가 가능성, 데이터 부족 위험을 반드시 표시
- 투자자문, 법률자문, 세무자문으로 오인될 수 있는 문구 금지
- 특정 투자 행위를 권유하지 말 것
- “수익 보장”, “확정 가치”, “반드시 상승” 같은 표현 금지

필수 Sub Agent 설계 기준:

- Data Intake Agent
  - 책임: 기업 기본정보, 재무자료, 시장자료, 경쟁사자료 입력 구조 담당
  - 입력: 기업 기본정보, 재무제표, 시장자료, 경쟁사자료, 내부 제공 자료
  - 출력: 정규화된 입력 데이터 구조, 누락 데이터 목록, 검증 필요 항목
  - 연결 대상: Financial Analysis Agent, Market & Competition Agent, Validation Coordinator Agent

- Financial Analysis Agent
  - 책임: 손익, 현금흐름, 성장률, 마진, 재무 건전성 분석 담당
  - 입력: 정규화된 재무자료, 손익계산서, 재무상태표, 현금흐름표, 매출·비용 구조
  - 출력: 재무분석 요약, 성장성 분석, 수익성 분석, 현금흐름 분석, 재무 리스크 목록
  - 연결 대상: Valuation Modeling Agent, Risk Review Agent, Report Builder Agent

- Valuation Modeling Agent
  - 책임: DCF, Multiple, PER, PSR, Comparable Company Analysis, Precedent Transaction Analysis 기반 가치평가 구조 담당
  - 입력: 재무분석 결과, 성장률 가정, 마진 가정, 할인율 가정, 비교기업 자료, 거래사례 자료
  - 출력: 시나리오별 기업가치 범위, 주요 가정표, 민감도 분석 구조, 밸류에이션 리스크
  - 연결 대상: Value Maximization Agent, Risk Review Agent, Report Builder Agent

- Business Model Agent
  - 책임: 사업모델, 수익모델, 고객군, 경쟁우위, 확장성 분석 담당
  - 입력: 기업 소개자료, 제품·서비스 정보, 고객군, 매출 구조, 운영 구조
  - 출력: 사업모델 분석, 수익모델 분석, 경쟁우위 요약, 확장성 평가, 취약점 목록
  - 연결 대상: Value Maximization Agent, Investor Narrative Agent, Report Builder Agent

- Market & Competition Agent
  - 책임: 시장규모, 성장성, 경쟁사, 산업 리스크 분석 담당
  - 입력: 산업자료, 시장규모 자료, 경쟁사 자료, 외부 리서치 자료
  - 출력: 시장성 분석, 경쟁구도 분석, 산업 리스크, 비교기업 후보 목록
  - 연결 대상: Valuation Modeling Agent, Business Model Agent, Risk Review Agent

- Value Maximization Agent
  - 책임: 기업가치 상승 레버, 개선 과제, 밸류업 전략 도출 담당
  - 입력: 재무분석 결과, 밸류에이션 결과, 사업모델 분석, 시장분석, 리스크 분석
  - 출력: 가치 극대화 레버, 실행 우선순위, 개선 과제, 밸류업 전략
  - 연결 대상: Investor Narrative Agent, Report Builder Agent, Validation Coordinator Agent

- Risk Review Agent
  - 책임: 재무 리스크, 시장 리스크, 실행 리스크, 과대평가 리스크 점검 담당
  - 입력: 재무분석 결과, 밸류에이션 결과, 시장분석 결과, 사업모델 분석 결과
  - 출력: 리스크 체크리스트, 과대평가 위험, 데이터 부족 위험, 보완 필요 항목
  - 연결 대상: Validation Coordinator Agent, Report Builder Agent

- Investor Narrative Agent
  - 책임: 투자자 설득 논리, IR 메시지, 반박 대응 구조 담당
  - 입력: 밸류에이션 결과, 가치 극대화 전략, 사업모델 분석, 시장분석, 리스크 리뷰
  - 출력: 투자자용 핵심 메시지, 예상 반박 대응, IR 논리 구조, 투자자 관점 보완사항
  - 연결 대상: Report Builder Agent, Validation Coordinator Agent

- Report Builder Agent
  - 책임: 내부 보고서, 투자자용 자료, 요약본 산출물 구조 담당
  - 입력: 모든 Agent의 분석 산출물
  - 출력: 내부 의사결정 보고서 구조, 투자자용 설명자료 구조, 최종 컨설팅 보고서 구조
  - 연결 대상: Validation Coordinator Agent

- Validation Coordinator Agent
  - 책임: Codex 검증 요청, 검증 결과 반영, 재작업 흐름 관리 담당
  - 입력: 각 Agent 산출물, Report Builder 산출물, Codex 검증 결과
  - 출력: 검증 요청 목록, 검증 실패 항목, 수정 지시, 재검증 상태
  - 연결 대상: Claude Code, Codex, LLM Wiki

검증 실패 시 흐름:

- Codex가 오류 또는 누락을 발견하면 /llm-wiki/validation-log.md에 기록한다.
- Claude Code는 오류 항목을 /llm-wiki/current-state.md에 반영한다.
- Validation Coordinator Agent가 관련 Agent로 되돌려 수정 작업을 지시한다.
- 수정 후 Codex에 재검증을 요청한다.
- 재검증 통과 시 /llm-wiki/decision-log.md와 /llm-wiki/current-state.md를 갱신한다.
- 통과 전에는 최종 산출물로 확정하지 않는다.

실제 작업 방식:

- 먼저 현재 작업 디렉터리 구조를 확인한다.
- 기존 파일이 있으면 덮어쓰기 전에 목적과 충돌 여부를 판단한다.
- 필요한 폴더가 없으면 생성한다.
- 위 파일 구조에 맞춰 문서를 생성한다.
- 각 문서는 실제 운영 가능한 수준의 항목형 구조로 작성한다.
- 불필요한 장문 설명은 제외한다.
- 각 문서가 서로 연결되도록 참조 관계를 명시한다.
- 마지막에 /llm-wiki/current-state.md와 /llm-wiki/handoff-prompt.md를 반드시 갱신한다.
- 모든 구축 결과에 대해 Codex 검증 요청용 체크리스트를 /llm-wiki/validation-log.md에 남긴다.

최종 출력 시 포함할 것:

- 생성한 파일 목록
- 각 파일의 목적
- 현재 완료 상태
- Codex 검증 요청 항목
- 다음 작업
- 다음 세션에서 사용할 handoff 요약

최종 출력 시 금지할 것:

- 특정 기업의 임의 가치 산정
- 임의 재무 수치 생성
- 투자 추천
- 수익률 보장
- 법률·세무 확정 판단
- 과도한 자동화 제안
- 실제 구현 불가능한 복잡한 구조
- 역할이 중복되는 Agent 구성
- LLM Wiki 없이 진행하는 방식
- 검증 없이 최종 확정하는 방식

이 작업은 “다음 단계에서 바로 구현 가능한 수준의 개발계획과 하네스 구축 산출물”을 만드는 것을 기준으로 완료하라.
